# Strands (Release 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any blog page can be marked a strand and carry an ordered list of that blog's posts; readers see the parts beneath the page's text and "Part N of M" with previous/next part on each post; authors and agents manage it from the page editor, the entry editor, `/api/v1` and MCP.

**Architecture:** One migration adds `pressroom_weblogpage.is_strand` and, on `weblogentry`, `strand_page_id` + `strand_position`. Membership lives on the post (zero or one strand by construction). `WeblogEntryManager` owns strand queries and writes, with a pure `StrandRules` class for validation and a pure `StrandPlace` for "Part N of M" arithmetic, so the editor, API and renderer share one implementation. Rendering adds two shared macros (parts list, strand bar) used by the three article themes.

**Tech Stack:** Java 25, Spring MVC, JSP admin, Velocity themes, JPA/EclipseLink, PostgreSQL 18, JUnit 5 + Testcontainers.

**Spec:** `docs/superpowers/specs/2026-11-15-ordering-strands-pages-design.md`, section "Release 2: strands" (criteria 9-18). Read it with this plan. Release 1 (ordering and pins) is shipped on master; its patterns (V047, `EntryPins`, `PinnedRowsRenderingTest`, `McpInstructions`) are the precedents to follow.

## Global Constraints

- Every new column defaults to today's behaviour: `is_strand boolean NOT NULL DEFAULT false`; `strand_page_id varchar(48) NULL REFERENCES pressroom_weblogpage(id) ON DELETE SET NULL`; `strand_position integer NULL`; index `(strand_page_id, strand_position)`. Migration `V048`, idempotent.
- A post is in zero or one strand; a strand's parts are posts of the **same blog**.
- Appending: position = max + 1 over **all** members of any status, trashed included (first part = 1). Positions need not be contiguous; numbering is computed. Moving a post to another strand never renumbers the old one. Trashing keeps strand and position.
- A **reader-visible part** = status PUBLISHED and `pubTime <= now`. N = rank among reader-visible parts by position (1-based); M = their count.
- A strand page not PUBLISHED, or not `is_strand`: its posts show no strand bar and use the blog's Older/Newer links. Never a link to a 404.
- Changing membership or order needs `WeblogPermission.POST` on the blog (the page editor's and publishing's level).
- Unticking `is_strand` while the page has parts (any status, trashed included) is refused. Deleting a strand page detaches its parts (strand cleared, posts kept) after a `data-confirm` naming the count; `ON DELETE SET NULL` is only the backstop.
- Every strand change that alters what a reader sees bumps `weblog.lastModified`.
- API: field errors are **400** with an `errors` entry naming the field (the API's convention). Removing a post from its strand through the API is `clear: ["strand"]` (the API never reads null as a value).
- Duplicating a post (`copyAsDraft`) does not copy its strand (as it does not copy its pin).
- Project gates (CLAUDE.md): TDD, JaCoCo floors, diff coverage ~90%, PMD/CPD/SpotBugs zero (suppress one-offs at the site with a reason), `-Xlint:all` zero warnings, name every `@RequestParam`, Velocity hazards (never write a zero-argument macro name with a leading `#` in a comment), escaping (entry titles emit bare; page titles through `$utils.escapeHTML`; JSP EL through `fn:escapeXml`).
- Run one class: `pgrep -f "[s]urefirebooter.*$(git rev-parse --show-toplevel)/app/target/" >/dev/null && echo BUSY || mvn -o -q -pl app test -Dtest=<Class>` (if BUSY, wait; never start a second build).
- Commit per task (local only). **Never push.**

## Review Focus

1. **A strand whose only reader-visible part is the current post**: "Part 1 of 1", no previous, next slot links back to the strand page. Test in Task 3.
2. **A part scheduled for later** (PUBLISHED, `pubTime` tomorrow, or SCHEDULED): not counted, not linked, until its time. Test in Task 2 (`StrandPlace`/query) and Task 3.
3. **`set_parts` / the Parts panel naming the same post twice, or an empty list**: duplicates are a 400 field error naming the post; an empty list removes every part. Test in Task 2 (`StrandRules`) and Task 5.
4. **Assigning a post to a page of another blog, or to a non-strand page, from the entry editor or `entries update {strand}`**: refused with a field error; nothing saved. Test in Tasks 4b and 5.
5. **Deleting a blog with strands** (`removePages` / weblog removal): no FK failure; posts and pages go as before. Test in Task 2.
